# 新能源汽车充电桩运营服务平台数据库代码说明

## 1. 项目结构

核心实现位于 `04_SQL脚本与数据库实施`，跨模块设计、验收与说明位于仓库根目录。

| 路径 | 内容 |
|---|---|
| `04_SQL脚本与数据库实施/install_all.sql` | SQLCMD 全组安装入口，按依赖顺序创建对象并加载种子 |
| `04_SQL脚本与数据库实施/sql/schema` | R、C、D、A1、B、A2 表结构与分区定义 |
| `04_SQL脚本与数据库实施/sql/constraints` | 主外键、检查约束、唯一约束及索引 |
| `04_SQL脚本与数据库实施/sql/views` | A1、B、A2、C、D 业务查询视图 |
| `04_SQL脚本与数据库实施/sql/routines` | 核价、设备状态、告警派单、企业月结、运营商结算等过程 |
| `04_SQL脚本与数据库实施/sql/queries` | Q01–Q05 五条多表查询和合订查询 |
| `04_SQL脚本与数据库实施/sql/seed` | R/A1/B/A2/C/D 基础及整合演示数据 |
| `04_SQL脚本与数据库实施/sql/acceptance` | 整合对象/行数验收与基线双向差集检查 |
| `04_SQL脚本与数据库实施/src/evplatform` | Python SQLAlchemy 持久层与业务服务 |
| `04_SQL脚本与数据库实施/tests` | pytest 持久层测试及 SQL 回归测试 |
| `docs` | 安全、备份恢复、查询执行计划、整合验收说明 |
| `scripts` | 执行计划采集与隔离恢复演练工具 |

## 2. SQL 安装顺序

全组数据库按以下顺序安装：

1. 加密密钥与加解密过程；
2. R/C/D/A1/B/A2 基础表；
3. 各业务线及跨线外键和索引；
4. A1/B/A2/C/D 视图；
5. B、A1、A2、C、D 存储过程和触发器；
6. R、B、C、D、A2 整合种子及 70 号覆盖数据。

开始前新建并选择专用空库 `EV_B_TEST`。脚本会检查数据库名，避免误装入其他库。加密种子需要在 SQLCMD 环境中提供 `EV_MASTER_KEY_PASSWORD`。详细顺序与本机命令见 [联调验收](联调验收.md)。

## 3. Python 持久层

依赖固定在 `04_SQL脚本与数据库实施/requirements.txt`。数据库连接由 `EV_DB_ODBC` 提供；通过 `evplatform.db` 创建 SQLAlchemy Engine 和 Session。

| 模块 | 主要职责 |
|---|---|
| `db.py` | 连接串读取、Engine 和 Session 工厂 |
| `models.py` | 核心声明式模型及对已安装 A1/B/A2 表的反射映射 |
| `orders.py` / `order_queries.py` | 个人订单开单和稳定分页 |
| `billing.py` | 调用 `usp_PriceChargingOrder` 核价 |
| `payments.py` | 支付、退款申请与完成，处理锁、幂等和事务 |
| `stations.py` | A1 场站分页和设备状态过程调用 |
| `enterprise.py` | 企业卡、车辆绑定、额度、企业订单结清、企业订单分页和优惠适用判定 |
| `a1_services.py` / `a2_services.py` | A1 状态变更及 A2 优惠券、个人发票、企业月结服务 |
| `services.py` | D/C 业务门面、权限检查与数据范围过滤 |
| `monitoring.py` | 监测数据批量写入，失败整批回滚 |
| `auth.py` | PBKDF2 密码哈希、登录失败锁定与会话超时判断 |
| `audit.py` | 在业务事务中追加共享操作审计 |
| `masking.py` | 手机号、车牌展示脱敏 |

涉及多步写入的服务由调用方管理 Session 事务；SQL Server 存储过程在数据库侧执行状态、约束与并发保护。企业订单结清入口是 `settle_enterprise_order`；优惠活动以场站关联、会员等级关联和 `member_level_scope` 判断适用性。

## 4. 测试与验收入口

- `python -m pytest tests -q`：运行 Python 持久层、权限、安全、事务与并发测试。
- `tests/test_*.sql`：逐个用 `sqlcmd` 执行 SQL 约束、视图、过程和查询回归。
- `sql/acceptance/02_verify_integration.sql`：只读核验 62 张表、逐表目标行数、权限矩阵和联调数据。
- `sql/acceptance/03_compare_baseline.sql`：把已安装结算结果与基线集合做双向差集。
- `python scripts/collect_plans.py <sqlcmd.exe路径>`：采集 Q01–Q05 IO 与实际执行计划，更新 `docs/plans/` 和查询执行计划报告。
- `python scripts/restore_drill.py`：对 EV_B_TEST 做全量与差异备份，恢复到随机命名临时库，执行 CHECKDB 和表数检查后删除临时库。

当前完整测试数字及详细结果见 [测试报告](测试报告.md)。

## 5. 维护约定

修改表结构时，同步检查跨业务外键、索引、视图、过程、种子、ORM、SQL/pytest 回归和整合验收。修改查询口径时，同时更新查询脚本、结果断言及执行计划。种子应可重复运行；测试使用专属数据并在事务中回滚或精确清理，不修改 EV_B_DEV。
