## 联调安装与使用

在专用空库安装前，将保存在受控位置的高熵主密钥口令注入 SQLCMD 进程环境的 `EV_MASTER_KEY_PASSWORD`。可使用由字母、数字和 `!` 组成的口令，例如用 `Ev9!` 作前缀并附加 32 个随机字节的十六进制。避免在变量值中使用 SQL 字符串引号；安装记录和 Git 中均不要保存口令。独立安装入口使用同一变量。

安装脚本创建数据库主密钥、证书 `Cert_EV_Sensitive` 与 AES-256 对称密钥 `Key_EV_Sensitive`。`usp_EncryptSensitive` 和 `usp_DecryptSensitive` 通过输出参数返回结果；过程关闭它自己打开的会话密钥。仅授权可信的 SQL 主体独立调用这两个过程，尤其应将解密权限与普通读取权限分开。应用记录查询还需校验账号和业务主体。

已有库的旧占位值不会随幂等种子更新。验收使用新安装的合成数据。`mask_phone()` 和 `mask_plate()` 用于显示，等值检索应按与落库一致的 Unicode 规范化规则计算摘要。

## 后续部署方案

- 手机号、车牌等需恢复的数据在应用服务使用带认证的加密。为每次加密生成独立 nonce，保存密钥版本及认证标签。数据库连接启用 TLS 并验证服务器证书。主密钥交由密钥管理服务，数据库和日志只保存密文及必要元数据。
- 等值检索先规范化输入，再计算独立检索密钥下的 HMAC-SHA-256。手机号与车牌值域较小，单独使用无密钥哈希不能抵御离线枚举。轮换需要评估 `plate_hash` 唯一键，迁移期间保持同一车牌的冲突检验。
- 常规界面仅展示掩码。根据角色和业务范围授予完整查看及敏感导出权限，默认导出脱敏结果。审计记录字段名、操作目的、审批编号和行数。发票邮箱与抬头等联调字段使用虚构值，正式部署按个人信息分级处理。
- 验收使用合成手机号和车牌，验证持久化值、掩码、跨主体访问拒绝、授权导出留痕及轮换后的检索结果。
