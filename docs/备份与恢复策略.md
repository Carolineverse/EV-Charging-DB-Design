# 备份与恢复策略

仓库的安装入口和种子可重建课程联调数据。基线 CSV 属于验收输入。`sql/maintenance/backup_restore.sql` 提供 `EV_B_TEST` 的全量、差异备份及带校验和的 `RESTORE VERIFYONLY`，默认依次生成两种文件。定时分开执行时使用脚本内 `FULL` 或 `DIFF` 模式，差异备份需要已有全量基线。脚本的恢复命令保留为注释，仅供隔离演练。

## 本机实测（2026-11-23，SQL Server 17.0 Express / EV_B_TEST）

| 项目 | 结果 |
|---|---|
| 全量备份 | 处理 2496 页（数据）+ 2 页（日志）= 2498 页，耗时 0.098 秒（约 199 MB/s） |
| 差异备份 | 成功，`RESTORE VERIFYONLY` 通过 |
| 备份校验 | `文件 1 上的备份集有效`；`RESTORE HEADERONLY` 返回 `BackupType=1`（全量）、`Compressed=0` |
| 落盘位置 | 实例默认备份目录 `...\MSSQL17.SQLEXPRESS\MSSQL\Backup\`（`SERVERPROPERTY('InstanceDefaultBackupPath')`） |

**实测中发现的两条环境限制（已处理）**：

1. **Express 版不支持备份压缩**——`BACKUP ... WITH COMPRESSION` 报错 1844，故脚本只用 `WITH CHECKSUM`，不压缩。
2. **备份到用户目录会失败**——`C:\Users\<账号>\...` 报错误 5（拒绝访问），因为 SQL Server 服务账号对该目录无写权限；改用实例默认备份目录后正常。

恢复演练（`WITH REPLACE` 到隔离库）仍保留为注释，**未在隔离实例上实际执行**。

## 拟定目标

| 项目 | 建议 |
|---|---|
| 备份周期 | 每周一次完整备份，每日差异备份。生产目标库使用完整恢复模式，并每 15 分钟备份事务日志。 |
| RPO / RTO | 生产初始目标为 RPO ≤ 15 分钟、RTO ≤ 2 小时。以成功演练和监控数据校准。 |
| 保留 | 日常备份初始保留 30 天，并保留符合团队归档要求的月度副本。备份须加密、限制访问并保留异地副本。 |
| 作业监控 | 对备份失败、日志链断裂、可用空间及异地复制延迟告警。将备份目录和加密证书恢复权限独立管理。 |

## 拟定恢复演练

1. 核对备份链、检查和及加密证书。模拟事故时在隔离实例、独立库名及数据路径上恢复，记录选定恢复点。
2. 恢复完整备份、对应差异备份和连续日志，按需要做时间点恢复，最后使目标库联机。执行一致性检查并记录输出。
3. 核对恢复点业务数据、权限矩阵及审计追溯。恢复到新实例时，使用受控保存的主密钥口令解锁数据库主密钥，配置该实例上的自动打开方式后验证密文往返。课程联调库可运行 `02_verify_integration.sql` 与 `03_compare_baseline.sql`，检查规定的行数和集合。
4. 记录备份时间、日志覆盖点、数据损失窗口、恢复与验证耗时和问题。完成证据归档后再判定 RPO、RTO 是否满足目标。生产演练建议至少每季度进行一次。
