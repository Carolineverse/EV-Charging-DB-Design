# 安全策略

---

## 已实现的机制

### 1.1 密码存储：PBKDF2 加盐哈希

- 算法：PBKDF2-HMAC-SHA256，**100,000 轮迭代**，**16 字节随机盐**。
- 存储格式：`pbkdf2_sha256$100000$<salt_hex>$<hash_hex>`，写入 `SysAccount.password_hash VARCHAR(255)`。
- 实现：`src/evplatform/auth.py` 的 `generate_salt` / `hash_password` / `verify_password` / `set_password`。

### 1.2 登录失败限制与账号锁定

- 每次密码错误：`SysAccount.failed_login_count + 1`。
- **连续 5 次失败**：账号置 `status = 0`（停用），后续登录直接拒绝。
- 登录成功：计数清零并写入 `last_login_at`。
- 失败计数在抛出异常**之前**提交，保证异常路径也会记录。
- 实现：`src/evplatform/auth.py` 的 `login()`，异常类型 `InvalidCredentials` / `AccountLocked`。

### 1.3 会话超时

- `session_expired(last_login_at, timeout_minutes=30)`：超过 30 分钟无活动即判定会话过期。
- 说明：该函数需由调用方（应用层）在每次访问时调用；本课程未实现 Web 会话中间件。

### 1.4 RBAC 权限判定

- 权限矩阵：`SysPermission` **70** 条，`RolePermission` **84** 条（R01 24 / R02 12 / R03 21 / R04 15 / R05 12）。
- 布尔判定：`services.py` 的 `has_permission(account_id, permission_code)`，检查账号状态、角色与权限状态。
- 数据范围：`RolePermission.data_scope` 取 `ALL` / `ASSIGNED` / `SELF` / `ENTERPRISE` / `PUBLIC` 五种。
- 场站级范围过滤：`services.py` 的 `filter_by_scope(account_id, scope)`，已接入告警分页查询（按 `ALARM_VIEW` 在数据库内过滤）。
- 订单、发票、结算等明细按各自业务主体（用户 / 企业 / 场站）在业务过程中校验。

### 1.5 敏感数据导出默认关闭

- `SENSITIVE_EXPORT` 只在 `SysPermission` 中**定义 1 条**，`RolePermission` 中**默认授权 0 条**。
- 验收脚本 `sql/acceptance/02_verify_integration.sql` 会检查 `1 / 0` 这两个值。

### 1.6 过程级状态与权限校验

| 过程 | 校验内容 |
|---|---|
| `usp_GenerateSettlement` | `ServiceCaseAssignment` 的 `case_type`、`case_id`（场站\|账期）、获派账号、有效期；`created_by` 必须等于获派账号 |
| `usp_ConfirmSettlement` / `usp_ApproveRedFlush` / `usp_ApproveCarryover` / `usp_ApplyCarryover` | 必须为启用的 R01，且审批人 ≠ 经办人 |
| `usp_RegisterDifference` / `usp_RegisterInvoice` | 必须为结算单获派账号本人 |
| `usp_DispatchWorkOrder` | 告警状态、是否已有在办工单、工程师是否在岗值班 |

### 1.7 审计与账务保护

- 账务与关键操作写入 `OperationLog`（含 `before_data` / `after_data`，JSON 格式受 CHECK 约束）。
- 触发器 `trg_OperationLog_Protect` **拒绝 UPDATE / DELETE**，日志只追加。
- 已知边界：拥有 DDL 权限的账号可以禁用触发器，该触发器是 SQL 权限之下的一层保护。

### 1.8 联调库的数据安全

- `EV_B_TEST` 只使用合成数据（虚构手机号、车牌、企业名与信用代码）。
- 事务与并发测试使用 `TST_` 前缀的专属账号/场站，测试结束在事务内清理；并发用例清理审计行时在**同一事务内**临时禁用并恢复 `trg_OperationLog_Protect`，恢复后才提交。
