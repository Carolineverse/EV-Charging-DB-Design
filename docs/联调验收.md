## 监控数据批量写入与验证

`evplatform.monitoring.insert_monitoring_batch()` 接收 `MonitoringSample` 序列。每条样本显式传入桩号和 `collected_at`。传入数据库本地时间的无时区时间值，按 `DATETIME2(3)` 存储。可选字段允许传 NULL。分区键由 SQL Server 计算。方法用现有的 `SessionLocal` 取得独立会话，通过一次多参数执行写入整批，正常退出时提交，任一行异常时回滚并向调用方抛出。空批次直接返回。

`tests/test_monitoring_batch.py` 只读取父桩，使用自己创建的 `TST_MON_` 报文。成功用例在另一会话按报文号重读样本。失败用例把缺失报文放在有效样本之间，验证 SQL Server 的 547 和 `FK_DeviceMonitoringData_report`，再用新会话按本次报文号确认整批无残留。

测试用 `B_DEMO_PILE01` 的 ASCII 字节计算 SHA-256，首字节为 `0x02`，模 4 为 2。2027-01 样本的计算列值为 `202701 × 10 + 2 = 2027012`。分区函数是 RANGE RIGHT，共 9 个边界，最高为 `2027010`。因此样本落入第 10 个分区，即 `[2027010, +∞)`。这避开了 2026-11/12 的键范围，也避开了当前联调 C 种子的 2026-09/10 样本。第 10 分区同时接纳后续范围的键。

## 数据口径与接口假设

### 企业订单结清口径

企业客户走对公月结，不逐单支付。企业订单的 `status='PAID'` 与 `settled_at` 由企业卡扣款侧在上游写入；本模块的月结过程 `usp_A2_GenerateEnterpriseSettlement` 以“已结清订单”为输入（要求 `status='PAID' AND settled_at IS NOT NULL`）。

持久层提供 `enterprise.settle_enterprise_order(order_id)` 落地该口径：充电结束即视为对公付款成立，置 `PAID`、`settled_at = end_time`、`paid_amount = gross_amount - discount_amount`。联调种子 `51_B_demo_enterprise_settlement.sql` 按同一口径构造订单，属已声明的接口边界，不是缺失实现。

### 优惠活动 target_audience 口径

物理结构设计与逻辑结构设计对该字段只给出“目标人群范围，用于按人群定向发券”的说明，未定义枚举值，因此 DDL 不设 `CHECK` 约束（与设计文档一致）。

定向发券的实际判定依据不是该文本字段，而是三张关系表加活动状态与有效期：

- `Promotion.status = 'ACTIVE'` 且当前时间落在 `valid_start_at` ~ `valid_end_at` 之间；
- `PromotionStation` 包含目标场站；
- `member_level_scope = 'ALL'`，或 `PromotionMemberLevel` 包含用户的 `UserMemberLevel.member_level_id`。

持久层 `enterprise.is_promotion_applicable(promotion_id, user_id, station_id)` 实现上述判定；`target_audience` 仅作展示标签，不参与判定。
